# TV alerts (Vetro Shard for Samsung TVs)

## Rule: check the Notification Center first
At the start of **every** request that touches this Shard, run `pwsh -File check-nc.ps1` (or
`GET http://192.168.1.7:8099/plugins/notification-center/api/api`). It compares the `version`, `enums`,
`fields` and `limits` with `.nc-api.json` and exits 1 when something changed. If it changed, read the new
field in `GET /api`, update `../NOTIFICACOES-ESTADO.md` and then use it. Never hardcode a field list
without checking; a field or mode the TV does not know is silently ignored or falls back to a default.

## Rule: send only through the Notification Center
This Shard never draws anything on the TV. Its only output is
`POST http://127.0.0.1:8099/plugins/notification-center/api/notify` (see `banner()` in `index.js`); the
Notification Center decides banner / full / overlay, sound, quiet hours and grouping. Do not launch apps,
play sounds or call `webapis`/`paplay` from here. Do not modify `tv-notification-center` for a feature of
this Shard.

Standalone project, split from the Notification Center repository. One Shard with three independent modules:
**sport** (football and other sports), **weather** and **news**. All of them send banners on top of whatever is running through the
**Notification Center** Shard (github.com/mclaudiopt/tv-notification-center), which must be installed on the same TV with its companion app
(Shard 0.2.0+, app 0.2.2+). The Shard id is still `match-alerts` so existing installations keep their config.

## What exists (v0.5.36)
- Proactive weather warnings: `weather.proactive {enabled,minutes,rain,wind,heat,storm,windKmh,heatC}` reads Open-Meteo's hourly arrays already fetched by `pollWeather`; `checkProactive()` emits one silent banner per phenomenon per hour, deduped through `ctx.config.weatherNotified` (max 60, restored in `start()`). Open-Meteo only (IPMA daily feed has no hourly data).
- Global banner limit: `banner()` enqueues instead of POSTing when 4 banners were already sent in the last 60 s (`BANNER_MAX_MIN`, `BANNER_GAP` 1 s, queue max 12). The queue drains on a real timer and on the next enqueue; `priority:"high"` (civil protection) always goes straight out. Since 0.5.33 the queue is **bounded**: when full, the oldest (stale) banner is dropped and logged instead of growing without limit. `/api/state` and `/api/last` expose `notify: {queued, sentMinute}` for diagnostics. A failed POST to the Notification Center is logged as `notify/error` instead of being silent. `stop()` clears the timer.
- **Goal simulation tab** (`config.sim.clubs[]`): a button per test club with its ESPN crest, name and score line. `POST /api/test-club {id}` calls the same `banner()` as real goals with `level` from the club, `mode:'overlay'`, `theme:'sport'`, `image` PNG, `duration:8`, `group:false` and **no sound** (no `golo`, no new sounds, no Notification Center changes). Default clubs: Sporting 2250 `ok`, Benfica 1929 `alert`, Porto 437 `info`, Feyenoord 142 `alert`. The list is editable in the panel and is independent of `football.clubs` (the followed clubs). `banner()` now forwards `theme`.
- **New tab "Proteção Civil"** (`config.civ`): polls IPMA `warnings_www.json`, the official ANEPC `avisos-a-populacao` HTML and Notícias ao Minuto RSS (keyword-filtered). District filter via IPMA `idAreaAviso` (Leiria = `LRA`, Caldas da Rainha), level switches (yellow off, orange/red on), ANEPC priority, stable id dedupe, baseline on first poll. `/api/state.civ` lists active warnings for the tab; `POST /api/test {kind:'civ'}` and `POST /api/poll {module:'civ'}` drive it. Since 0.5.35 the Test button always announces the highest-priority allowed active warning (or a clearly labelled sample when none is active), even if it was already seen or the module is switched off — the old test silently did nothing in those cases. Only Notification Center banners are sent.
- **Panel layout (0.5.36)**: seven tabs (**SETUP**, Weather, News, Civil protection, Football, Other sports, **Technical**). The old General tab is now called SETUP. Its Modules card has four switches that control tab visibility: `modules.sport` shows/hides both Football and Other sports, `modules.weather` shows/hides Weather, `modules.news` shows/hides News, and `config.civ.enabled` shows/hides Civil protection (the two civ switches stay in sync). SETUP and Technical are always visible. Hiding a tab never deletes its saved parameters, and Previous/Next skip hidden tabs. The diagnostics card (watched lines, log, provider health and Clear log) lives in the Technical tab, matching the Notification Center Shard's own Technical pane. Every tab uses a single-column `.stack` of full-width cards, each split into collapsible `<details class="sec">` blocks whose `<summary>` is the section heading; Save/Test rows stay outside them so they are always reachable. Mode/Sound/Volume are grouped in a single "Style" section per tab for consistency. The goal simulation lives inside Football ("Goal simulation" + "Edit the test clubs"), so there is no separate tab. The tab bar is `position: sticky`, a Previous/Next pair at the bottom of every tab moves between tabs (and scrolls to the top), and the header has **Test all** and **Save all** buttons (the first runs the sport/weather/news/civ tests in order, 1 s apart) plus an "unsaved changes"/"saved at HH:MM" indicator that the 20 s refresh does not reset. Since 0.5.34 the Diagnostics card shows a provider health card (last success, last failure, consecutive failures) and a **Clear log** button (`POST /api/clearlog`); since 0.5.35 it lives in the Technical tab.
- `index.js` (Shard, plain **ES5**, Node 4.4 compatible), `ui.html` (panel with seven tabs and collapsible sections, no `<form>`: the Vetro frame has no `allow-forms`), `manifest.json` (no `exec`), `check-nc.ps1` (drift check of the Notification Center API). Since 0.5.30 the code is split into `providers/espn.js` (scoreboard, events, summary, next-fixture and caches), `providers/af.js` (optional API-Football, key injected from `ctx.config`) and `news.js` (RSS/Google News, baselines and per-poll budget). They use local `require()` (allowed by the Vetro host), never touch the notify path and receive HTTP/config/scheduler deps by injection; bundle = 8 files, well under 20 files / 512 KB. Since 0.5.32 all shipped sources are ASCII (`\u` escapes in JS, HTML entities in markup).
- Modules, each with its own timer and status: **sport** (ESPN public scoreboard or API-Football), **weather** (Open-Meteo, place chosen in the panel, interval 5-240 min, quiet hours 23h-07h), **news** (public RSS + Google News, interval 5-240 min, first fetch is a baseline, then new headlines only, 1-3 per source).
- **Custom places**: SETUP → Weather → *Find* searches Open-Meteo's geocoder by name (`geocoding-api.open-meteo.com`), *Add selected* saves `{id:'c<geocoder id>', name, lat, lon}` in `config.weather.custom` (max 10) and selects it. `allPlaces()` = built-in `PLACES` + custom; it feeds the panel list, place validation and `pollWeather()`. Removing the selected custom place falls back to Lisboa.
- **Football: several clubs at once** (`football.clubs[]`), each with its own competition list (`comps[]`) and an optional club-news flag. The panel pre-ticks the country's league and cup plus the European cups. A competition is fetched once and shared by every club following it (`compCache`, 20 s live / 2 min / 10 min empty), and only a match with one of the clubs can reach the screen.
- **Other sports**: several picks (`others.picks[]`), NBA / MLB / NHL / NFL / F1, each with its own alerts (start, half, end, score). **Several picks of the same sport are allowed** (0.5.30): team picks are keyed by `sport|teamId`, whole-race picks (F1) by `sport|eventId` (older configs fall back to `sport|name`). Since 0.5.31 the panel fills the race selector from `/api/races` and `findMatch()` selects the event by that id (then by a distinctive name, then the first race), so two Grands Prix no longer follow the same race. Since 0.5.33 `/api/races` reads ESPN's whole season (`?dates=YYYY`, 25 events in 2026, cached 6 h, sorted by date with a `past` flag) and falls back to the current scoreboard if that request fails; the panel disables **Add** instead of storing a pick without an event id when no races are available. Each pick has its own watch key (`other:<sport>:<teamId||name>`), baseline and `watchStatus`; the ESPN scoreboard is still fetched once per competition and shared. `publicCfg().maxPicks` = 10; duplicates are deduped and the panel disables **Add** at the cap.
- **News: several sources** (`news.feeds[]`), each with its own baseline; club news is a Google News search per club. `gnewspt` (Google News PT, `https://news.google.com/rss?hl=pt-PT&gl=PT&ceid=PT:pt-150`) is the default and only source for a fresh install. Since 0.5.34 the club-news switches live **only in the Football tab**: the duplicate "Club news" card was removed from the News tab, so the same club headlines are never shown/configured twice. Headline de-duplication across different sources remains out of scope.
- Panel auto-saves when a club (max 3, `MAX_CLUBS`), other-sport pick or news source is added/removed or a club-news flag changes; `publicCfg().maxClubs` tells the panel the cap.
- Adaptive sounds (0.5.0): `refreshSounds()` reads `enums.sound` from the NC self-description at start and every 10 min; `banner()` replaces an unknown sound with `alert`. `golo` is used when the NC offers it (it was added, withdrawn and re-added in 0.10.0).
- Notification style per section: **banner**, **full** and **overlay** (needs Notification Center 0.8.0+; `level` colours the stripe, `sound` plays at once, opacity is a NC setting). Sound per section; sport uses `reward` for every event (SOUND map and the PRE-MATCH warning), muted by the module's sound switch. Each section has its own `volume` (10-100) forwarded in `banner()`; the silent goal-simulation buttons omit both `sound` and `volume` (they are a test, not a real alert).
- Every notify carries `source: "tv-alerts"`; sport alerts also send `group: false` so similar banners in the same minute are both shown, and `image` with the ESPN team crest PNG as the overlay icon (`icon` emoji is the fallback). `logoFor()` only builds a URL for ESPN providers/known sports. Civil-protection warnings use NC 0.13 `priority: "high"` so they bypass quiet hours.
- Football events from ESPN: goal, opponent goal, card, substitution (via the summary endpoint, kept also after the final whistle), disallowed goal, kick-off, half-time, full time. All new goals between two polls are announced, not only the first. Cross-club dedupe (`seenEvent`): two of my clubs in the same match do not announce the same goal twice. Goal banners put the scorer's name in both title and message (`ex.player`); `espnEvent()` prefers an explicit `scorer` participant, then `athletesInvolved`, then a name parsed from the event text, and a score-only goal reuses the scorer from `m.events`.
- Routes under `/plugins/match-alerts/api/`: `state` (internal, full config), `last` (0.5.30, public read-only widget endpoint: `{version, at, historyAt, status, watches, next, civ, last, notify, health, log}` with CORS `*`, no config/key/providers/feeds), `teams` (POST), `races` (0.5.31, F1 event ids/names for the picker; 0.5.33: whole season, sorted, with `past` and `season` flags), `geocode` (POST with `name`, returns candidates with coordinates), `config`, `test`, `poll`, `clearlog` (0.5.34, POST, empties the in-memory log), `keycheck` (validates the API-Football key and reports remaining daily requests without returning it). Provider health is recorded centrally in `getVia()` by host (espn, open-meteo, civ, rss) and exposed as `health` in `state`/`last`.
- Banners: `POST http://127.0.0.1:8099/plugins/notification-center/api/notify` (fields in `docs/API.md` of that project and in `../NOTIFICACOES-ESTADO.md`). Some feeds are plain HTTP (CNN), so `getUrl()` picks `http` or `https` from the URL.
- Panel API base: the panel page is served at `/plugins/<id>/api/ui` (dashboard) or `/plugins/<id>/s/<session>/api/ui` (opened page). `ui.html` strips the trailing `/ui` and resolves the API from there, so requests go to `…/api/state`, never `…/api/api/state` (the doubled `api/` 404s, which is why the panel showed nothing at all in 0.4.0/0.4.1). The Vetro host answers those pages with `Content-Security-Policy: sandbox allow-scripts` and an opaque origin, so the host sends the CORS headers itself (Origin `null`).
- Config migration: the 0.2/0.3 single team under `config.sport` and the 0.1 flat `provider`/`teamId`/`on` become `config.football.clubs[0]` on first read; `config.sport` is deleted on the next save.
- Robustness (0.4.6): a failed competition is logged and cached for 2 min without failing the other clubs; `sumPending`/`sumWait` make two clubs in one match share one summary request; news has a global budget of 4 banners per poll, at least 1 s apart, and unsent headlines stay fresh for the next poll; an empty scoreboard is retried in 5 min, a `pre` match within 30 min in 20 s.
- Next fixture (0.5.0): `football.nextGame {enabled, minutes}` (default on, 30 min). ESPN only accepts one `?dates=YYYYMMDD` per request (a range returns 400) and the team `/schedule` endpoint is stale, so `scanNext()` walks days 0-7 across the club's competitions, reuses today's `compCache`, stops at the first day with a match and caches per day+competition for 1 h (`dayCache`). `nextGame[watchKey]` (1 h TTL) feeds `/api/state.next` and the panel line; `warnIfDue()` sends one overlay banner per fixture inside the configured window (`nextWarned[fixtureId]`), cleared when the match goes live; `persistNextWarned()` saves the ids to `ctx.config.nextNotified` (max 20) and `start()` restores them so a TV reboot cannot repeat the banner. API-Football uses `/fixtures?team=&next=1` instead.

## Scope / not open
- The three items requested in the last round (several picks of the same sport, public `/api/last`, split into `providers/espn.js` / `providers/af.js` / `news.js`) are **done in 0.5.30**; 0.5.31 fixes the F1 case where every race pick followed `evs[0]`; 0.5.34 removes the duplicate club-news UI. There are no other open ideas in `MELHORIAS.md`.
- API-Football with a real key and de-duplicating headlines across different sources are **out of scope by decision** — ESPN is the provider and each news source shows its own headlines. The duplicate *club-news configuration* in the News tab was removed in 0.5.34; club news is set only in Football.
- NC profile `tv-alerts` belongs in the Notification Center repo, not here. Panel search/filter and `both`+`action` goal mode were declined.
- News baselines are persisted since 0.5.14 (`ctx.config.history.newsSeen`), not memory-only.
- `overlay` mode is done and tested on the TV; do not change `tv-notification-center` for it. `image` with a PNG URL is already forwarded by `banner()` (ESPN crest), `icon` stays a single emoji fallback.

## Build, install, test
- Tooling: Vetro's `vetro-plugin.cjs` (github.com/andrearicci93/vetro, `app/scripts/`): `check <folder>`, `pack <folder> <outDir>` (delete an old `.vplugin` from the folder first).
  **Never pack the project folder itself**: the packer bundles every subfolder, so `dist/` would be embedded in the `.vplugin` (88 KB -> 261 KB). Copy `index.js`, `ui.html`, `manifest.json`, `README.md`, `LICENSE` **and the `providers/` subfolder** (`espn.js`, `af.js`) plus `news.js` to a clean staging folder and pack that, with `dist` as the output folder. The packer recurses into subfolders and the host unpacks them before loading `index.js`, so the local `require()` calls resolve.
- Tests: 20 mocked scripts are versioned in `tests/` and require `../index.js`. Run `node tests/run.js` or `npm test`; the runner requires exit 0 **and** `ALL GOOD` in the output, so a script without assertions cannot pass silently. `.github/workflows/test.yml` runs them on every push/PR without a TV. Do not copy `tests/` into the packing staging folder.
- Build: `pwsh -File build.ps1` runs `check-nc.ps1` first, copies the 8 shipped files into `build/stage`, runs `vetro check` and `vetro pack` into `dist/`, prints the sha256, and with `-Install` disables → installs → enables → verifies on the TV. The packer is vendored in `tools/vetro/` (MIT) so nothing depends on `%TEMP%`. `build/` and `dist/` are gitignored; `vetro check` on the project folder itself still fails because it bundles `dist/`, so always build from the clean staging folder. Since 0.5.33 the script also refuses to pack if `AGENTS.md`, `README.md`, `MELHORIAS.md` or `package.json` do not mention the manifest version, and prunes old bundles from `dist/` after a successful pack (keeps the current and the previous one).
- Install on a TV with Developer mode: `POST http://<TV-IP>:8099/plugins/install` with the bundle as body and header `X-Vetro-Sha256: <sha256 of the file>`, then `POST /plugins/match-alerts/enable`. Update = disable, install, enable.
- Shard limits: ES5, <= 20 files, <= 512 KB, text only, no downloaded code, no `eval`. Keep sources ASCII (`\u` escapes, `String.fromCharCode`).
- Panel buttons show a spinner then a green or red flash (`act()` in `ui.html`).
